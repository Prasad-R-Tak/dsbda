Introduction to Data Science & Big Data

Definition
What is Data Science?
Data Science is an interdisciplinary field that uses scientific methods, algorithms, processes, and systems to extract knowledge and insights from structured and unstructured data.

It combines Statistics, Mathematics, Programming (Python, R), Domain Knowledge, and Machine Learning.

Definition
What is Big Data?
Big Data refers to extremely large datasets that cannot be stored, processed, or analyzed using traditional data processing tools.

Question & Answer — Paper 1

Q1 · Part A
Explain 6 V's for defining Big Data along with the factors responsible for data explosion.
8 Marks

The 6 V's of Big Data

1. Volume

Volume refers to the enormous amount of data generated every second from various sources such as social media, IoT devices, transactions, and sensors. The scale of data ranges from terabytes to petabytes and beyond. Traditional storage systems are incapable of handling such massive quantities of data, which necessitates distributed storage solutions like HDFS and cloud storage.
Example: Facebook generates over 500 terabytes of data every single day.

2. Variety

Variety refers to the different types and formats of data being generated. Data now includes Structured data (tables, spreadsheets), Semi-structured data (XML, JSON, emails), and Unstructured data (images, videos, audio, social media posts).
Example: A hospital generates structured patient records, semi-structured lab reports in XML, and unstructured MRI scan images — all simultaneously.

3. Velocity

Velocity refers to the speed at which data is generated, collected, and must be processed. In many modern applications, data must be processed in real time or near real time to be useful.
Example: Credit card companies must analyze transactions within milliseconds to detect fraud before it causes financial loss.

4. Veracity

Veracity refers to the quality, accuracy, and trustworthiness of data. Big Data often contains noise, inconsistencies, missing values, and duplicate records. Poor quality data leads to incorrect analysis and wrong business decisions.
Example: Social media data contains fake profiles, bots, and spam — making it unreliable without proper cleaning.

5. Value

Value refers to the usefulness and business benefit extracted from Big Data. Raw data by itself has no meaning — it must be processed and analyzed to derive actionable insights that create real business value.
Example: Amazon analyzes customer purchase history to recommend products, directly increasing sales revenue.

6. Variability

Variability refers to the inconsistency in the flow and meaning of data over time. The same data can mean different things in different contexts, and the rate of data generation fluctuates.
Example: The word "hot" in a weather report means high temperature, but in music it means trending — such contextual inconsistency is a major challenge.

Factors Responsible for Data Explosion

  • Social Media Platforms: Billions of users on Facebook, Instagram, Twitter generate massive amounts of text, images, and videos every second.
  • Internet of Things (IoT): Billions of connected devices — smart sensors, wearables, industrial machines — continuously generate and transmit data.
  • Mobile Devices: Widespread use of smartphones enables continuous generation of data through calls, messages, app usage, GPS, photos, and videos.
  • E-Commerce & Digital Transactions: Online shopping platforms, banking systems, and digital payment services generate millions of transaction records daily.
  • Cloud Computing: Availability of affordable cloud storage encourages organizations to store more data than ever before.
  • Multimedia Content: Video streaming platforms like YouTube and Netflix along with digital photography contribute enormous volumes of unstructured data daily.
Key Points to Remember
  • 6 V's = Volume, Variety, Velocity, Veracity, Value, Variability
  • Data Explosion is the root cause — it created all 6 V's
  • 80% of world's data is unstructured (Variety)
  • Traditional tools fail because of all 6 V's together
Q1 · Part B
List and explain data processing infrastructure challenges in Big Data with suitable examples.
7 Marks

Definition

Big Data infrastructure challenges refer to the technical, operational, and organizational difficulties faced when building and maintaining systems to store, process, and analyze large-scale data.

Challenge 1: Data Storage and Management

Storing petabytes of data generated continuously from multiple sources is a major challenge. Traditional relational databases have fixed storage limits and cannot scale to accommodate Big Data volumes. Organizations must invest in distributed storage systems that can expand horizontally.
Example: Walmart processes 2.5 petabytes of customer transaction data every hour — storing this on a single server is completely impossible.

Challenge 2: Real-time Data Processing

Many Big Data applications require data to be processed instantly as it arrives. Traditional batch processing systems introduce delays that are unacceptable in time-sensitive scenarios.
Example: A stock trading platform must process millions of price updates per second and execute trades in milliseconds — any delay results in financial loss.

Challenge 3: Data Heterogeneity and Integration

Big Data arrives from multiple sources in different formats — structured databases, semi-structured logs, and unstructured social media posts. Integrating all these heterogeneous data types into a unified processing system is technically challenging.
Example: A healthcare organization must integrate structured patient records, semi-structured XML doctor notes, and unstructured MRI scan images into one analytical system.

Challenge 4: Data Quality and Veracity

Big Data collected from diverse sources often contains errors, missing values, duplicates, and inconsistencies. Poor quality data directly affects the accuracy of analysis and business decisions.
Example: Customer data collected from online forms may contain duplicate entries, misspelled names, and missing phone numbers.

Challenge 5: Data Security and Privacy

Big Data systems store sensitive personal, financial, and medical information. Protecting this data from unauthorized access and breaches is a major challenge. Organizations must also comply with data protection regulations such as GDPR.
Example: A bank's Big Data system storing millions of customer account details is a prime target for hackers.

Challenge 6: Scalability of Infrastructure

As data volumes grow continuously, the infrastructure must scale up efficiently without disruption. Designing systems that can add more nodes and storage capacity seamlessly is a key challenge.
Example: Instagram experiences sudden spikes in data during major events — the infrastructure must scale instantly to handle the load.

Challenge 7: Cost of Infrastructure

Building and maintaining Big Data infrastructure requires significant investment in hardware, software, networking, and skilled personnel. For smaller organizations, this cost is a major barrier.
Example: Setting up an on-premise Hadoop cluster requires millions of rupees in hardware and maintenance costs alone.

Q2 · Part A
List and explain choices for reengineering the data warehouse.
8 Marks

Why Reengineer the Data Warehouse?

Traditional Data Warehouses were designed for structured, slow-moving data. With the arrival of Big Data, they became inadequate because they could not handle unstructured data, real-time streams, or petabyte-scale volumes. Reengineering involves modernizing the data warehouse by integrating new technologies.

Choice 1: Adopting ELT over ETL

Traditional ETL (Extract → Transform → Load) transforms data before loading. Reengineered ELT (Extract → Load → Transform) loads raw data first, then transforms as needed. This is faster and more flexible, especially for large volumes of unstructured data.

Choice 2: Integration of Data Lakes

A Data Lake is a centralized repository that stores raw, unstructured, and semi-structured data in its native format. Integrating Data Lakes alongside the Data Warehouse creates a complete analytical ecosystem that supports all data types.

Choice 3: Moving to Cloud-Based Data Warehouses

On-premise warehouses are replaced or supplemented with cloud-based solutions such as Amazon Redshift, Google BigQuery, and Microsoft Azure Synapse. Cloud warehouses offer elastic scalability, pay-as-you-go pricing, and automatic maintenance.

Choice 4: Incorporating Distributed Processing Frameworks

Reengineered data warehouses integrate Apache Hadoop and Apache Spark to handle large-scale data processing. These frameworks can process petabytes of data in parallel across hundreds of machines.

Choice 5: Real-time Streaming Integration

Traditional warehouses only supported batch loading. Reengineering integrates real-time streaming pipelines using Apache Kafka and Spark Streaming, enabling live dashboards, instant fraud detection, and real-time customer personalization.

Choice 6: Schema-on-Read instead of Schema-on-Write

Traditional approach (Schema-on-Write) requires data to conform to a predefined schema before storage. Schema-on-Read stores data in raw format and applies the schema only when reading for analysis, providing much greater flexibility.

Choice 7: Use of NoSQL Databases

Traditional warehouses rely exclusively on relational databases. Reengineering introduces NoSQL databases such as MongoDB, Cassandra, and HBase to handle unstructured and semi-structured data with horizontal scalability.

Q2 · Part B
Explain shared-everything and shared-nothing architectures in detail with respect to Big Data.
7 Marks

Shared-Everything Architecture

A system design in which all processors share a common pool of memory, storage, and other resources. The entire system operates as a single unified machine.
  • All nodes share common RAM, CPU, and Disk storage
  • Communication happens through shared memory — very fast
  • Typically implemented as Symmetric Multiprocessing (SMP) systems
  • Limitation: Poor scalability — contention for shared resources as processors increase
  • Big Data: NOT suitable — cannot scale to petabyte-scale workloads

Shared-Nothing Architecture

A system design in which each node is completely independent and has its own dedicated CPU, memory, and disk storage. Nodes communicate only through a network.
  • Each node is self-contained with own CPU, RAM, and Disk
  • Data is horizontally partitioned across all nodes
  • Adding more nodes increases both storage and processing capacity
  • Forms the foundation of Hadoop, Cassandra, and most Big Data systems
  • Big Data: IDEAL — scales horizontally, fault tolerant, processes in parallel

Q1 · Part A
"Data explosion plays an important role in Big Data" — Justify the statement with proper explanation along with examples.
8 Marks

Introduction

Data Explosion refers to the rapid, massive, and continuous growth of data being generated every second from countless digital sources. It plays a central and foundational role in the emergence and importance of Big Data.

"Without Data Explosion, Big Data would not exist. It is Data Explosion that created the need for Big Data technologies, infrastructures, and analytics."

Justification 1: Data Explosion Created the Need for Big Data Storage

Before the digital era, data was limited and manageable by traditional databases. Data Explosion caused data volumes to grow from gigabytes to petabytes and exabytes, making traditional storage completely inadequate. This directly gave rise to Big Data storage solutions such as HDFS, Cloud Storage, and Data Lakes.
Example: YouTube receives 500 hours of video uploads every single minute. Storing this requires distributed Big Data storage infrastructure — not traditional databases.

Justification 2: Data Explosion Introduced the Concept of Data Variety

As data exploded from multiple sources, it arrived in completely different formats — structured, semi-structured, and unstructured. This variety of data formats is a direct consequence of data explosion and is one of the defining characteristics of Big Data.
Example: Amazon generates structured transaction records, semi-structured product review JSONs, and unstructured customer images — all simultaneously at massive scale.

Justification 3: Data Explosion Demanded Real-Time Processing

The speed at which data explodes requires systems that can process it in real time. This gave rise to the Velocity dimension of Big Data and the development of real-time processing frameworks like Kafka and Spark Streaming.
Example: During a cricket World Cup final, Twitter experiences millions of tweets per minute — sentiment analysis tools must process this exploding stream in real time.

Justification 4: Data Explosion Raised Data Quality Challenges

As data exploded from diverse, uncontrolled sources, quality and reliability became questionable — introducing the Veracity challenge of Big Data. Fake profiles, sensor errors, and duplicate records became widespread.
Example: During elections, social media platforms experience an explosion of posts — many from fake accounts and bots, requiring sophisticated Big Data quality management tools.

Justification 5: Data Explosion Created Business Value Opportunities

The explosion of data from customer interactions provided organizations with an unprecedented opportunity to understand customers, predict trends, and make data-driven decisions — creating the Value dimension of Big Data.
Example: Netflix analyzes the explosion of viewer data to power its recommendation engine, which is responsible for 80% of content watched on the platform.

Conclusion

Data Explosion is not just related to Big Data — it is the root cause and driving force behind Big Data. Every characteristic of Big Data (all 6 V's) is a direct consequence of Data Explosion. Without understanding and managing Data Explosion, Big Data analytics and infrastructure would have no purpose or foundation.

Q1 · Part B
Differentiate between Big Data and Small Data with their processing architecture.
7 Marks

Definitions

Small Data: Datasets small enough in volume, variety, and velocity to be stored and processed using traditional data management tools such as relational databases and spreadsheets.

Big Data: Extremely large, diverse, and fast-moving datasets that exceed the capacity of traditional tools and require specialized distributed infrastructure.

VarietyMostly structuredStructured + Semi + Unstructured
VelocitySlow, batch processingHigh speed, real-time

ToolsExcel, MySQL, OracleHadoop, Spark, Kafka, NoSQL
ProcessingSequential, single machineParallel, distributed cluster
ScalabilityVertical (upgrade one machine)Horizontal (add more machines)
SchemaFixed, predefinedDynamic, flexible
ExampleStudent marks databaseFacebook user activity logs

Small Data Processing Architecture

Uses a Centralized Single-Server Architecture — all data is stored and processed on a single machine using ACID-compliant relational databases (MySQL, PostgreSQL). Processing is sequential and vertical scaling is used to improve performance. Simple to set up and query using standard SQL.

Big Data Processing Architecture

Uses a Distributed Multi-Node Architecture — data is partitioned and distributed across multiple independent nodes. Processing is done in parallel across all nodes simultaneously using MapReduce or Spark. Horizontal scaling (adding more nodes) handles growing data. Follows Shared-Nothing Architecture where each node is completely independent.

Q2 · Part A
Define the relation between Artificial Intelligence, Statistical Learning and Machine Learning with sample example.
8 Marks

Introduction

Artificial Intelligence, Statistical Learning, and Machine Learning are three closely related and overlapping fields in Data Science.

"AI is the destination, Machine Learning is the vehicle, and Statistical Learning is the fuel that powers it."

1. Artificial Intelligence (AI)

AI is the broadest and most encompassing field that focuses on building machines and systems capable of performing tasks that normally require human intelligence — such as reasoning, learning, decision making, perception, and language understanding. It is the ultimate goal — creating intelligent machines. It encompasses many subfields including ML, NLP, Computer Vision, Robotics, and Expert Systems.
Example: A self-driving car perceives its environment through cameras and sensors, reasons about what actions to take, and makes decisions like braking or turning — mimicking human driving intelligence.

2. Statistical Learning

Statistical Learning is the mathematical and theoretical foundation that uses probability theory, statistics, and mathematical models to analyze data, identify patterns, and make inferences. It focuses on understanding and explaining relationships between variables and emphasizes model interpretability — not just prediction but understanding why. Core techniques include Regression, Hypothesis Testing, Probability Distributions, and Bayesian Inference.
Example: A statistician uses linear regression to model the relationship between a patient's age, weight, and blood pressure — not just to predict it but to understand which factors influence it most.

3. Machine Learning (ML)

Machine Learning is a subset of Artificial Intelligence that uses Statistical Learning principles to enable computers to automatically learn patterns from data and improve their performance without being explicitly programmed. Instead of manually writing rules, the machine discovers rules automatically from data. It works best with large datasets and focuses primarily on prediction accuracy.
Example: A spam email detector is trained on thousands of labeled emails, learns patterns automatically, and classifies new incoming emails without any manual rule writing.

Data Warehouse: A centralized repository that collects, stores, and manages large volumes of structured, historical data from multiple sources for reporting and analysis.

Data Mining: The process of discovering hidden patterns, correlations, anomalies, and useful knowledge from large datasets using statistical, mathematical, and computational techniques.

Example from Data Science Perspective

Scenario: A bank wants to understand and predict customer loan defaults

Data Warehouse Role: The bank's Data Warehouse stores 10 years of historical customer data — loan amounts, repayment history, credit scores, income levels — all cleaned, structured, and organized for easy access.

Data Mining Role: Data Mining algorithms are applied on this warehouse data to discover patterns — for example, customers with income below ₹3 lakhs and more than 2 existing loans have an 85% probability of defaulting. This pattern was hidden in the data and revealed only through Data Mining.

Key Points to Remember
  • Data Warehouse = Storage system; Data Mining = Analysis process
  • DW uses ETL; Data Mining uses KDD
  • Data Warehouse feeds data INTO Data Mining for analysis
  • Together they form the core of Data Science pipeline
  • DW answers "What data?" | Data Mining answers "What patterns?"
